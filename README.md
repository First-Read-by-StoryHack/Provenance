# Provenance
First Read provenance key manifest and canonical signature format
# First Read — provenance key mirror

This repository publishes the public keys First Read uses to sign documents, so that a signature can
be verified **without First Read's involvement, permission, or continued existence.**

## Why this repository exists

First Read signs every completed pipeline document at the moment a writer saves it. A signature is
only useful if the key that made it can be found by someone we have no relationship with — a studio,
a guild, an opposing party in a dispute, a court-appointed expert, years later.

A key published only on our own servers fails that test. If we are acquired, go dark, or simply
decline to help, every signature we ever made becomes uncheckable. **This mirror is how that is
avoided.** There is a second, independent copy in DNS:

```
dig +short TXT _provenance.storyhack.io
```

## This is a MIRROR

The authoritative manifest is generated by First Read at
`https://www.storyhack.io/api/provenance/manifest`. This file is a copy.

**If the two disagree, something is wrong.** Trust neither automatically. The DNS record is the
tiebreaker: it carries the current public key directly, is controlled at the domain registrar rather
than by the application, and is the hardest of the three to alter quietly.

## Append-only

Keys are **superseded, never removed**. Each entry carries `validFrom` and `validUntil`.

Deleting a key from this file does not tidy it up — it makes every signature that key ever produced
permanently unverifiable. If you are editing this file and about to remove an entry, stop.

## How to verify a signature

`verify-example.mjs` is a complete, dependency-free implementation. Node 16+:

```
node verify-example.mjs binding.json document.txt
```

Or implement it yourself. The full specification:

**1. Select the key.** Use the entry whose `validFrom <= record.savedAt < validUntil`
(`validUntil: null` means current). Do not assume the newest key.

**2. Fingerprint rule.** SHA-256, hex, of the text after: CRLF converted to LF, trailing spaces and
tabs stripped from each line, then the whole string trimmed. A reformat is therefore not treated as
tampering; any change to wording, ordering or punctuation is.

**3. Canonical payload.** A JSON array, in exactly this order:

```
[version, docId, showId, ownerId, contentFingerprint, profileFingerprint, docType, savedAt]
```

For voice-profile records rather than documents:

```
[version, profileId, ownerId, fingerprint, boundAt]
```

**4. Verify.** Ed25519 over the UTF-8 bytes of that JSON array. The `signature` field is base64.

## What a valid signature proves, and what it does not

**It proves:** First Read produced this exact document, against the recorded voice profile, at the
recorded time — and the text has not changed since.

**It does not prove** that a particular named human wrote it. The account behind `ownerId` is
verified by email address only. Stronger identity binding is a separate mechanism; when it exists,
records will state which checks were performed rather than leaving it to be inferred.

Anyone quoting a verification result as proof of personal authorship is reading it wrong, and we
would rather say so here than be quoted saying otherwise.

## Provenance start date

Document signing began **2026-08-18**. Documents saved before that date carry no signature. Their
absence is not evidence of anything.
